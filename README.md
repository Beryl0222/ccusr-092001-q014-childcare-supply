# 普惠托位供给测算

面向老城区党群中心、公房、办公用房改造普惠托育点的**供需与补助资金月度测算后端**。
卫生健康部门据此判断新增托位是否覆盖需求最紧迫的街区，并让每笔补助都可追溯到
所采用的政策版本。仅依赖 Python 标准库（SQLite），无外部运行时依赖。

## 能力总览

- **需求侧只收聚合口径**：网格按月份、托位类型录入需求数与紧迫数，不接收任何家庭身份明细。
- **场地与合规**：一个场地支持**分阶段启用**（独立合规结论、合规容量、开/闭月份）；
  仅“合规 + 已到启用月 + 未关闭”分期下、且机构当月状态为“运营”的班型才计入供给。
- **跨街道服务**：场地可备案服务多条街道；派位时本街道优先，跨街道名额单独标记，
  物理座位不会被重复分配。
- **候补匿名去重**：受理端只提交一次性家庭去重标识，服务端 HMAC-SHA256 后立即丢弃原值；
  同一家庭跨街道、跨月份重复申报只产生一条候补。派位按紧迫 → 分数 → 登记先后。
- **机构状态机**：规划/建设/备案/运营/暂停/退出，支持**临时停办与复工**；
  暂停期间不计供给、不计提运营补助。
- **政策版本化**：政策按月生效、可标记**追溯生效**；月度资金测算冻结为不可变运行，
  重算生成新运行并把旧运行置为 superseded（快照保留）。
- **补助核对与追回**：机构自报与系统核定逐条比对——重复申报拦截、虚高申报驳回、
  涨价冲减运营补助、停业/提前退出按承诺月数比例追回建设补助；
  追溯政策产生**补差链或追回链**，净支付 = 原申报 + 有效补差 − 累计追回。
  （普惠承诺的是收费上限，中途降价不视为违约。）
- **可解释**：建设建议记录逐月缓解了哪个供需运行下的多少缺口；
  `/claims/{id}/explain` 给出每笔补助所用政策版本、匹配规则、计算口径、补差与追回。
- **并发安全**：写事务一律 `BEGIN IMMEDIATE`；容量带乐观锁版本号，
  下调不得低于任何月份的在托峰值，班型容量合计不得超过分期合规上限，
  派位在事务内强校验“在托数 < 合规容量”。
- **职责最小授权**：规划员、资金员、受理员、审计员四类角色各有端点权限；
  家庭相关接口只返回匿名计数；所有写操作入审计日志。

## 数据最小化与角色

| 角色 | 职责 | 关键端点 |
| --- | --- | --- |
| `planner` 区域规划人员 | 网格需求、场地/分期、机构、班型、供需测算、建设建议 | `/sites`、`/phases`、`/supply/runs`、`/recommendations` |
| `funding` 资金管理人员 | 价格承诺/核查、政策版本、申报受理、资金测算 | `/policies`、`/claims`、`/funding/runs`、容量/状态变更 |
| `intake` 街道受理人员 | 候补匿名登记（唯一可写候补的角色） | `/waitlist` |
| `auditor` 审计监督人员 | 只读 + 审计日志 | `GET` 多数查询、`/audit-log` |

家庭去重标识在请求处理后不落库、不入日志；库中仅存 64 位 HMAC 十六进制键。
任何列表/汇总接口都不返回 `anon_key` 或原始标识。

## 快速开始

```bash
python3 service.py --check            # 配置与存储自检
python3 service.py --port 8000        # 启动 HTTP 服务（默认 childcare.db）
CHILDCARE_DB=/path/to.db python3 service.py --port 8000
curl localhost:8000/health
```

内置演示持票（生产应替换 `ApiApp(tokens=...)`）：

```
planner-demo-token / funding-demo-token / intake-demo-token / auditor-demo-token
```

调用示例：

```bash
curl -X POST localhost:8000/sites \
  -H "Authorization: Bearer planner-demo-token" \
  -H "Content-Type: application/json" \
  -d '{"name":"党群中心托育点","street":"东街"}'
```

## 典型月度流程

1. 规划员录入网格聚合需求、场地分期合规结论、机构与班型容量。
2. 受理员匿名登记候补家庭（只交一次性标识）。
3. 规划员 `POST /supply/runs` 冻结当月供需快照、派位，查看缺口并登记建设建议。
4. 资金员维护价格承诺与实际收费，发布政策版本。
5. 资金员 `POST /funding/runs` 核定补助；机构可先申报，由系统比对核定。
6. 政策追溯调整时重算月份，系统自动生成补差/追回链；用 explain 接口向各方解释。

## 代码结构

```
childcare/
  domain.py   枚举（取值以 domain.json 为准）、月份工具、状态机、错误类型、角色
  storage.py  SQLite schema 与仓库（事务、HMAC、容量约束、不可变运行/快照）
  engine.py   SupplyEngine（供需/派位/建议）、FundingEngine（计提/补差/追回/解释）
  api.py      HTTP 路由、持票鉴权、角色矩阵、字段白名单、审计
service.py    入口（--check / 启动服务，保留 /health）
tests/        场景与并发、API 测试
```
